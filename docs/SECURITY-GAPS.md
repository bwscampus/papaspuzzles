# Security gaps: Papa's Puzzles

This is an audit against the class [Production Standard](../.claude/skills/production-standard/references/standard.md),
done in October 2026. Rule IDs (AUTH-2, API-4, …) refer to that document. The `production-standard`
agent skill checks the same rules, so run it before you finish any change to auth, the database,
API routes, or deploy config.

**Status key**

- **Fixed**: done on branch `security/production-standard`.
- **Open**: a student task.
- **Owner**: a setting in GitHub or Railway that a teacher or founder has to change; code can't fix it.

## Summary

The code started from a strong base:

- All SQL is parameterised.
- Passwords are hashed with scrypt and compared in constant time.
- Reset tokens are hashed, single-use and expire.
- Credit spending is transactional, with row locks.
- Admin routes are gated, and identity comes from the session.
- Uploads are checked by their actual bytes.
- Styling uses one Tailwind token palette, and TypeScript runs in strict mode.

The serious problem was **identity**. Credits, history and admin rights were all keyed by email,
and nothing proved that the person signing up owned that email. This branch fixes that.

**Decision: existing accounts are not backfilled as verified.** Before this change, anyone
could have registered someone else's email, so a backfill would make any existing takeover permanent.

Every existing user, **including founders and admins**, verifies once:

- by clicking the link they get from "Resend the link" on My Trades, or
- by completing a password reset, which also marks the email verified because the reset link
  went to the same inbox.

Until an admin has verified, `/admin` returns 403 for them.
